部署策略

比較 In-place、Rolling、Immutable、Blue/Green 等持續部署策略
學習目標： 部署設定差異 · Blue/Green 實作 · 分段部署降低風險

1

重點概念

Key Concepts · In-place → Rolling → Immutable → Blue/Green
🔄
01

In-place 部署

In-Place Deployment

直接在既有執行個體上更新版本，速度快但會有停機時間。

🎢
02

Rolling 部署

Rolling Deployment

分批逐步更新機群，新舊版本並存，零停機但需考量雙版本相容性。

🏗️
03

Immutable 部署

Immutable Deployment

建立全新基礎設施部署新版本，失敗時只需終止新 Auto Scaling 群組即可回滾。

🔵🟢
04

Blue/Green 部署

Blue/Green Deployment

併行維護兩套環境，透過流量切換部署，出問題可立即切回原環境。

⚙️
05

CodeDeploy 部署設定

Deployment Configurations

EC2 用 OneAtATime/HalfAtATime/AllAtOnce；ECS/Lambda 另支援 Canary/Linear。

🌐
06

DNS 漸進式切換

Gradual DNS Cutover

用 Route 53 將流量從 Blue 環境逐步轉移到 Green 環境並持續監控。

🚩
07

功能旗標/暗啟動

Dark Launch

新舊程式碼路徑並存，用 feature flag 控制上線，適合對子集使用者測試。

✂️
08

分段部署

Segmentation

依區域/可用區/單機（Canary）分段部署，降低故障影響範圍並加快回滾。

✓

隨堂測驗考點

Knowledge Checks
Knowledge Check 1
哪種部署策略是用全新基礎設施取代舊版本？
✓

Immutable（不可變）部署。

Knowledge Check 2
分段部署「不」具備的效益是？
✓

加快整體部署速度不是分段部署的目的，降低風險與快速回滾才是。

⭐

一句話總結

沒有單一最佳部署策略——依風險承受度在 In-place/Rolling/Immutable/Blue-Green 間權衡取捨。
